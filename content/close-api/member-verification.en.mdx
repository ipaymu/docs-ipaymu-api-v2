The Member Verification API submits an iPaymu account verification request as a **member**.

## Endpoint

**URL**: `{{baseUrl}}/api/v2/member-verification`
**Method**: `POST`

| Environment | URL                                                     |
| :---------- | :------------------------------------------------------ |
| Sandbox     | `https://sandbox.ipaymu.com/api/v2/member-verification` |
| Production  | `https://my.ipaymu.com/api/v2/member-verification`      |

## Request Headers

This endpoint uploads files, so use `Content-Type: multipart/form-data`. The `va`, `signature`, and
`timestamp` headers are still required — see [headers & signature](/close-api).

| Header         | Value                 |
| :------------- | :-------------------- |
| `Content-Type` | `multipart/form-data` |
| `va`           | `{{va}}`              |
| `signature`    | `{{signature}}`       |
| `timestamp`    | `{{timestamp}}`       |

## Request Body (multipart/form-data)

| Parameter                | Type | Required | Description                                                    |
| :----------------------- | :--- | :------- | :------------------------------------------------------------ |
| `account`                | text | Yes      | iPaymu VA number to verify.                                   |
| `birthday`               | text | Yes      | Date of birth (format `YYYY-mm-dd`).                         |
| `birthplace`             | text | Yes      | Place of birth.                                               |
| `gender`                 | text | Yes      | `L` = Male, `P` = Female.                                     |
| `national_id`            | text | Yes      | National ID (KTP) number, **exactly 16 digits**.             |
| `province`               | text | Yes      | Province (from the [Area API](/close-api/area)).             |
| `city`                   | text | Yes      | City/Regency (from the Area API).                           |
| `district`               | text | Yes      | District (from the Area API).                                |
| `village`                | text | Yes      | Village (from the Area API). Area names are matched against master data and must nest correctly. |
| `postal_code`            | text | Yes      | Postal code.                                                  |
| `address`                | text | Yes      | Address (max. 200 characters).                              |
| `bank_code`              | text | Yes      | Bank code (from the [Bank List](/close-api/bank-list)).     |
| `bank_number`            | text | Yes      | Bank account number.                                         |
| `bank_account`           | text | Yes      | Account holder name. Must match the account name or the account's company name. The `bank_code` + `bank_number` pair must not already be registered to another account. |
| `npwp_no`                | text | No       | Tax ID (NPWP) number.                                        |
| `national_id_photo`      | file | Yes      | KTP file.                                                     |
| `selfie_photo`           | file | Yes      | Selfie holding the KTP.                                      |
| `passbook_photo`         | file | Yes      | Photo/scan of the bank passbook showing the account number and holder name. |

All files accept `.jpg`, `.jpeg`, `.png`, `.pdf`, max. 2MB. The member endpoint does **not**
accept `business_license_photo` — that document belongs to
[Merchant Verification](/close-api/merchant-verification).

## Example Request

This endpoint uses `multipart/form-data`, so send form fields — not JSON.

```bash
curl -X POST https://my.ipaymu.com/api/v2/member-verification \
  -H "va: 1179000899" \
  -H "signature: <signature>" \
  -H "timestamp: 20260908120000" \
  -F "account=1179000899" \
  -F "birthday=1990-05-17" \
  -F "birthplace=Denpasar" \
  -F "gender=L" \
  -F "national_id=5171010101900001" \
  -F "province=ACEH" \
  -F "city=KABUPATEN ACEH SELATAN" \
  -F "district=BAKONGAN" \
  -F "village=KEUDE BAKONGAN" \
  -F "postal_code=23773" \
  -F "address=Jl. Merdeka No. 10" \
  -F "bank_code=002" \
  -F "bank_number=1234567890" \
  -F "bank_account=Budi Santoso" \
  -F "national_id_photo=@ktp.jpg" \
  -F "selfie_photo=@selfie.jpg" \
  -F "passbook_photo=@buku-tabungan.jpg"
```

<Callout type="warn">
  **Signing multipart requests.** Compute the signature over the string `{}` — not over the
  form contents. The server supports this path specifically for requests carrying files. If
  you try to sign the whole body it will be rejected: file fields are included and encoded as
  `{}`, which the server then normalises again to `""` — very easy to get wrong. See
  [header & signature](/close-api).
</Callout>

## Where Each Value Comes From

The most common mistake is mixing up **code** and **name**:

| Parameter                                  | Source                                       | Send the   | Example |
| :----------------------------------------- | :------------------------------------------ | :--------- | :----- |
| `province`, `city`, `district`, `village`  | [Area](/close-api/area)                      | **`name`** | `ACEH`, `BAKONGAN` |
| `postal_code`                              | [Area](/close-api/area) — village level  | `postal_code` | `23773` |
| `bank_code`                                | [Bank List](/close-api/bank-list)            | **`code`** | `002` (Bank Rakyat Indonesia) |

<Callout type="warn">
  `bank_code` takes the bank **code** (`002`), not its name (`Bank Rakyat Indonesia`).
</Callout>

<Callout type="info">
  `bank_account` must match the account name or the account's company name.
</Callout>

## Example Response

```json
{
  "Status": 200,
  "Success": true,
  "Message": "Verification success",
  "Data": {
    "verification_id": 22567,
    "verification_status": {
      "code": -2,
      "desc": "PROCESSING",
      "state": "PROCESSING_ADMIN",
      "step": null,
      "notes": null
    }
  }
}
```

When the submission is rejected by an admin, `notes` carries the per-section
remarks and `step` points to the first step that must be fixed:

```json
{
  "Status": 200,
  "Success": true,
  "Message": "Verification success",
  "Data": {
    "verification_id": 22567,
    "verification_status": {
      "code": -1,
      "desc": "UNCOMPLETED",
      "state": "UNCOMPLETED",
      "step": "profile",
      "notes": {
        "profile": ["ID card photo is blurry", "Name does not match the ID card"],
        "bank": "Passbook is unreadable"
      }
    }
  }
}
```

## Verification Status

| Code | Desc          | Description                                               |
| :--- | :------------ | :-------------------------------------------------------- |
| `-2` | `PROCESSING`  | Account is being verified; nothing to act on.            |
| `-1` | `UNCOMPLETED` | Member action required: the submission was rejected, or it is still an unsubmitted draft. |
| `1`  | `VERIFIED`    | Account is verified.                                     |
| `0`  | `BASIC`       | Account is not verified yet.                             |

### Additional fields

| Field   | Description                                                                |
| :------ | :------------------------------------------------------------------------- |
| `state` | The precise state behind `code`: `BASIC`, `VERIFIED`, `PROCESSING`, `PROCESSING_ADMIN`, `INCOMPLETE`, `UNCOMPLETED`. |
| `step`  | The step the merchant must fix or continue (`profile`, `business`, `bank`, `document`, `application`). `null` when there is none. |
| `notes` | Per-section admin rejection remarks. `null` when the submission was not rejected. Each value may be a string or an array of strings. |

<Callout type="warn">
  Code `-2` means the submission is **still under review**, not rejected. Do not
  tell the merchant that verification failed until `code` is `-1`.
</Callout>

<Callout type="info">
  The `province`, `city`, `district`, and `village` values must come from the [Area API](/close-api/area),
  and `bank_code` from the [Bank List](/close-api/bank-list).
</Callout>
